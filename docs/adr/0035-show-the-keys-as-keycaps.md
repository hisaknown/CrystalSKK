# ADR-0035: 小窓は押すキーを枠で囲んで見せ、Windows 11 の見た目に揃える

- ステータス: Accepted
- 日付: 2026-09-25
- 関連: ADR-0015, ADR-0019, ADR-0020, ADR-0024, ADR-0025, ADR-0026

## 背景

候補の窓は、四角い枠の中に `a: 漢字` のような行を並べ、選んでいる行は地と文字の
色を入れ替えて示していた。GDI で描いていたので、文字は粗く、丸みも半透明も
扱えなかった。利用者は、見た目が野暮ったいので、モダンで簡素なものにしたいと
言った。

## 決定

### 押すキーを枠で囲む

- **押すキーは、角の丸い枠 (キーキャップ) で囲んで本文の左に出す。** `a:` の
  ような記号は使わない。枠はどのキーでも同じ大きさの正方形にし、本文の書き出し
  を揃える。キーは刻印に合わせて大文字で出す。
- 候補の一覧では行を選ばない (選ぶのはキーを押すことである)。動的補完の一行も、
  受け取るキーを同じ枠で出す。
- Tab で補完を巡っているあいだはキーを出さず、選んでいる行に角の丸い帯を敷き、
  左端に細い印を立てる。**印の幅はどの行にも空けておき、選ぶ行が変わっても
  本文の書き出しを動かさない。**

### 窓の形は DWM に任せる

- 窓の角は DWM に丸めさせ (`DWMWCP_ROUNDSMALL`)、影を付ける (`CS_DROPSHADOW`)。
- 影が出るなら枠は引かない (`DWMWA_COLOR_NONE`)。影を切っているときと
  ハイコントラストのときは、DWM に丸みに沿って `border` の色で引かせる。
- Windows 10 のように丸められないときは、これまでどおり四角い枠を自分で描く。
- カーソルのそばのモードの窓 (ADR-0025) も同じ形にし、絵のまわりの余白を丸みの
  分だけ広げる。二つの窓の DWM への頼みは `popup` にまとめた。

### 地を透かす

- 窓の地は DWM に透かさせる (`DWMSBT_TRANSIENTWINDOW`、Windows 11 のメニューと
  同じ Acrylic)。明暗は地の色の明るさで教える。
- 透かしたままでは、後ろが明るいと暗い窓の文字が読めない。そこで地の色を設定の
  `backdrop_opacity` (百分率、雛形では 65) の濃さで重ねる。
- 「透明効果」を切っているとき、ハイコントラストのとき、Windows がこれを知らない
  とき (Windows 10、Windows 11 の 22H2 より前) は、透かさずに地の色で塗る。
- 透かした地は窓が前面でないと単色に落ちる。小窓は焦点を奪えないので、
  `WM_NCACTIVATE` をいつも前面として扱わせる。

### 色

- 枠と印の色は設定の `key` で決める。雛形では `"accent"` にした。
- **選んでいる行の `"system"` は、`COLOR_HIGHLIGHT` ではなく地と文字から作る。**
  帯の地は地に文字の色を 1 割ほど混ぜた色、文字は本文と同じ色にする。強調の色で
  塗ると帯が重く、同じアクセントの印も埋もれる。色を直に書けば、それが使われる。
- 雛形の地と文字は、明暗どちらの組も色で直に書く。明るい組は `"#F9F9F9"` と
  `"#000000"`、暗い組はこれまでどおり `"#2B2B2B"` と `"#FFFFFF"` である。
  標準の地の色 (`COLOR_WINDOW`) は真っ白で Windows 11 のメニューとも違い、
  ダークモードにも従わない。**`"system"` と名乗るなら本当にシステムの色で
  なければならない**ので、システムにふさわしい色が無いところは色で書く。
- ハイコントラストのときは、設定にかかわらず、選んでいる行も含めてシステムの色
  に従う (ADR-0026)。

### 描き方

- 二つの窓は Direct2D と DirectWrite で描く (`draw`)。GDI では小さな丸みが
  なめらかにならず、半透明も扱えない。描く先はアルファを持たせ、地を透かせる
  ようにしてある。
- モードの窓の絵は、これまでどおりビルドのときに SVG から各大きさに描いた濃さを
  使い (ADR-0024)、拡大率に合う大きさを画素そのままで置く。SVG を動くときに描く
  (`ID2D1DeviceContext5`) ことはしない。Direct2D が扱える SVG は一部に限られ、
  描いておいた大きさで足りている。
- モードの窓は重ねた窓 (`WS_EX_LAYERED`) をやめた。DWM が地を透かさないためで
  ある。クリックは `WM_NCHITTEST` に `HTTRANSPARENT` を返して下へ通す。これは
  同じスレッドの窓にしか通らないが、下にあるのは入力先のアプリの窓で、同じ
  スレッドにある。

### 大きさと書体

- 設定の `[popup]` に書く。`scale` (百分率) はモニターの拡大率に掛け合わせ、
  文字も余白も絵もまとめて大きくする。
- `font` と `font_size` (ポイント) は、`"system"` ならメッセージの書体に従う。
  行の高さやキーの枠は文字の高さから決めているので、文字だけ大きくしても
  釣り合いは崩れない。

## 結果

- 雛形の値を変えても、すでにある設定ファイルの値は書き換えない (ADR-0020)。
  明るい組の地と文字は、利用者が手で直すまで `"system"` のままである。
  足りない項目 (`key`、`backdrop_opacity`、`[popup]`) は導入のときに書き足される。
- 透けて見えるかどうかは、Windows の版と設定と、背後の窓による。Windows 10 では
  これまでに近い見た目 (四角い窓、単色の地) のままになる。
