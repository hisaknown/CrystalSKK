# ADR-0007: TIP の導入には管理者権限が要る

- ステータス: Accepted
- 日付: 2026-09-22
- 関連: ADR-0006 を置き換える / PRD §10

## 背景

[ADR-0006](0006-register-the-tip-per-user-during-development.md) は、開発中の
TIP を `HKEY_CURRENT_USER` に登録すれば管理者権限なしで済む、としていた。
**これは誤りだった。**

実際に登録を試すと、COM のクラス登録は HKCU に書けたが、入力方式の登録
(`ITfInputProcessorProfileMgr::RegisterProfile`) が `E_FAIL` で失敗した。
レジストリを調べたところ、この環境の入力方式はすべて
`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\CTF\TIP` に置かれていた。
利用者ごとの `HKEY_CURRENT_USER\Software\Microsoft\CTF\TIP` にもキーはあるが、
そちらは機械全体に登録済みの TIP に対する利用者ごとの設定であって、
TIP の定義そのものではない。

先行実装も同じ制約を受けている。SKK日本語入力FEP のインストーラは
「インストール」ボタンで管理者権限を取得すると明記している。

ADR-0006 の誤りは「COM のクラスを利用者ごとに登録できる」ところまでは
正しく、「だから導入全体が管理者権限なしで済む」と早合点した点にある。

## 決定

**TIP の導入には管理者権限が要る**ことを前提にする。

1. COM のクラス登録も `HKEY_LOCAL_MACHINE` に書く。入力方式が機械全体に
   登録される以上、クラスだけを利用者ごとにしても辻褄が合わない。昇格が
   別の管理者アカウントで行われた場合、利用者ごとの登録は別の利用者の
   領域に書かれてしまい、誰からも見えなくなる。
2. DLL の置き場所も `%ProgramFiles%` にする。全利用者のあらゆるプロセスに
   読み込まれる DLL を、権限のない者が差し替えられてはならない。
   書き込みに管理者権限が要ることは、ここでは利点である。
3. `crystalskk-setup` は権限が足りなければ**自分を昇格して呼び直す**。
   利用者は UAC の確認に応じるだけでよい。別のシェルを開き直させない。
4. 登録の解除は、利用者ごとの領域も消す。ADR-0006 の時期に書かれたものが
   残っている可能性があるため。

## 帰結

- 導入と削除のたびに UAC の確認が出る。ADR-0006 が避けようとした「確認を
  惰性で押す癖」は、結局避けられない。せめて確認の回数を増やさないよう、
  昇格は一度きりにして、その中で全部を済ませる。
- 開発の反復は、**登録した DLL とビルド成果物が別物である**ことで確保する。
  `%ProgramFiles%` に写してから登録するので、IME を有効にしたままでも
  `cargo build` は通る。入れ替えのときだけ昇格が要る。
- 昇格した側は別のコンソールで動くため、その出力は元のコンソールに出ない。
  伝えたいことは一時ファイル経由で戻す。
- **ADR-0006 は誤りとして置き換える。** 調べずに「できるはず」と書いた
  結果であり、実際に試していれば初めから分かった。登録のような環境依存の
  判断は、書く前に一度動かすこと。

- **昇格した側の `HKEY_CURRENT_USER` は、この利用者のものとは限らない。**
  別の管理者の資格情報で昇格すれば、消したいのとは違う利用者の登録を
  消して終わる。利用者ごとの後始末は**昇格する前に**済ませる。
