# ADR-0018: 印は文書に出さない

- ステータス: Accepted (`▽` `▼` の扱いは ADR-0033 で改めた)
- 日付: 2026-09-23
- 関連: ADR-0017, PRD Q-09

## 背景

SKK は未確定の状態を `▽` `▼` `*` で示す。Emacs の SKK から続く見慣れた顔で
あり、状態が一目で分かる。

一方で、**記号は文書に混ざる**。書いている文の中に `▽` が挟まると、そこだけ
文字の並びが乱れる。`▽おく*り` は四文字のかなに二つの記号が割り込んでいる。

ADR-0017 で下線が部分ごとに変わるようになった。**状態を示すものが二つに
なった**ことになる。

## 決定

**二つは役目が違う。分けて扱う。**

```
▽おく*り   →   おく␣り
```

| | 役目 | 文書に出すもの |
|---|---|---|
| `▽` `▼` | **状態**を表す | 何も出さない |
| `*` | **境**を示す | 空白 |

状態は下線で分かる。見出し語は点線、送り仮名は破線、候補は太い実線
(ADR-0017)。記号まで並べると、同じことを二度言うことになる。**空白を置く
のも同じで、書いている文が一文字ぶん右へずれるだけになる。**

境のほうは下線に任せきれない。点線と破線は見分けが付きにくいので、空白で
区切りを見せる。

## 取り消したら区切りは消える

`▽おく*り` から `▼送り` へ進み、そこで取り消すと `▽おくり` に戻る。
**送り仮名は残り、区切りだけが消える。**

ddskk も CorvusSKK も既定でこうする。ddskk の `skk-delete-okuri-when-quit`
は nil が既定で、docstring がそのまま書いている。

> nil であれば、送り仮名を含めた見出し語をそのまま残して▽モードに入る。
>   例）"▽な*く -> ▼泣く -> C-g -> ▽なく"

CorvusSKK も `DelCvPosCncl` が既定 TRUE で、区切りだけを落とす。

一貫性を理由に区切りを残す作りにしていたが、**そのままでは続きを打つのに
一度消さなければならない**。「取り消して打ち直す」のが取り消しの目的で
ある以上、続けられる形に戻すほうが素直だった。

## CLI は記号のまま

ターミナルに下線は引けない。**そこでは記号が唯一の手がかり**になる。

同じ `Preedit` から違う見せ方をしているだけで、食い違ってはいない。印を
独立した区切り (`Role::Marker`) として持たせてあるので、**どう見せるかは
front end の裁量**になっている。

## 帰結

- 区切りの `*` は `Okuri` の中に埋め込まれていたが、印として独立させた。
  埋め込んだままだと、この選択ができなかった。
- **見出し語と送り仮名の線の差は、いま点線と破線でほとんど出ない。**
  ADR-0017 では「境は `*` が担っている」としていたが、その `*` は空白に
  なった。空きがあるので境は見えるものの、線だけで見分けたいなら選び直す
  余地が残る。
- 記号を好む人のために戻せる場所は、定数二つ (`MARKER_TEXT` と
  `SEPARATOR_TEXT`) にしてある。設定で選べるようにするときの置き場所になる。
- **先人に訊いてよかった。** 「一貫しているから」で決めかけたが、ddskk も
  CorvusSKK も同じところで別の答えを出しており、理由もあった。
