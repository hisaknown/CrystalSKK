# ADR-0010: 入力モードは区画に書いて伝える

- ステータス: Accepted (入切を書く部分は ADR-0012 が覆した)
- 日付: 2026-09-22
- 関連: ADR-0009

## 背景

入力モードを示す表示 (トレイの「あ / A」) を出そうとして、言語バーの
項目を実装した。項目は登録でき、シェルは `GetIcon` を何度も呼び、
モードを変えると呼び直しもした。返した絵は Windows に読ませて確かめた
ところ妥当だった。**それでも何も表示されなかった。**

CorvusSKK を読んで理由が分かった。入力モードは、言語バーの項目に絵を
返すだけでは伝わらない。TSF には「区画」(compartment) という、入力方式と
外の世界が値をやり取りする仕組みがあり、
`GUID_COMPARTMENT_KEYBOARD_INPUTMODE_CONVERSION` に書いた値が
「いまどのモードか」として読まれる。**Windows の表示はそちらを見ている。**

こちらはこの区画に一度も書いていなかった。絵を用意する話だと思い込んで
いたが、実際には**状態を伝える話**だった。

## 決定

入力モードが変わるたびに、区画へ書く。

| モード | 書く値 |
|---|---|
| ひらがな | `NATIVE｜FULLSHAPE｜ROMAN` |
| カタカナ | 上に `KATAKANA` を足す |
| 半角カタカナ | `NATIVE｜ROMAN｜KATAKANA` (全角の印を落とす) |
| 全角英数 | `ALPHANUMERIC｜FULLSHAPE` |
| 半角英数 | `ALPHANUMERIC` (値は 0) |

組み合わせは日本語入力の慣例に従う。`GUID_COMPARTMENT_KEYBOARD_INPUTMODE_SENTENCE`
にも書く。SKK は文法解析をしないが、書かないと「変換方式が決まっていない」
扱いになる。

有効化の直後にも書く。何も書かないうちは、表示が決まらない。

## 帰結

- 言語バーの項目は残す。区画が状態を伝え、項目が絵と操作を担う。
  どちらも要る。
- モードと値の対応は純粋な関数なので、試験で押さえられる。実機でしか
  確かめられない部分を、できるだけ小さくしている。
- **「表示が出ない」を「絵の問題」と決めつけたのが遠回りの原因だった。**
  絵を三度直したが、どれも表示が出ない理由ではなかった (そのうち二つは
  それ自体が本物の誤りだったので、直したこと自体は無駄ではない)。
  症状から原因を推し量る前に、動いている実装が**何をしているか**を
  見るほうが速い。
