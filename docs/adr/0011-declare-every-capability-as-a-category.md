# ADR-0011: 使える場面は分類として名乗る

- ステータス: Accepted
- 日付: 2026-09-22
- 関連: ADR-0010

## 背景

二つの症状が出ていた。

- トレイに入力モードの表示が出ない。区画に書いても (ADR-0010) 変わらない
- **スタートメニューの検索欄では、CrystalSKK を選ぶことすらできない**

前者を「絵の問題」と考えて三度直し、次に「状態の伝え方の問題」と考えて
区画を実装した。どちらも症状は変わらなかった。

後者の報告で筋道が見えた。検索欄は隔離された場面 (AppContainer) で動く。
そこで選べないということは、**その場面で使えると名乗っていない**という
ことになる。

TIP は分類 (category) を登録して、自分に何ができるかを宣言する。
**名乗らない能力は無いものとして扱われる。** こちらは
`GUID_TFCAT_TIP_KEYBOARD` 一つしか登録していなかった。

CorvusSKK は八つ登録している。その中に
`GUID_TFCAT_TIPCAP_SYSTRAYSUPPORT` (トレイ表示に対応) と
`GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT` (隔離された場面で動ける) があった。
二つの症状は、同じ漏れの別の顔だった。

## 決定

能力を分類として名乗る。

| 分類 | 意味 |
|---|---|
| `TIP_KEYBOARD` | キーボードから入力する TIP である |
| `TIPCAP_SECUREMODE` | ログオン画面のような場面でも動ける |
| `TIPCAP_UIELEMENTENABLED` | 候補一覧などをシステム側に扱わせられる |
| `TIPCAP_INPUTMODECOMPARTMENT` | 入力モードを区画で伝える |
| `TIPCAP_COMLESS` | COM の登録に頼らず読み込める |
| `TIPCAP_IMMERSIVESUPPORT` | ストアアプリやスタートメニューで動ける |
| `TIPCAP_SYSTRAYSUPPORT` | トレイの入力表示に対応する |

表示属性の分類 (`DISPLAYATTRIBUTEPROVIDER`) は登録しない。実装して
いないため。**できないことを名乗っても仕方がない。**

## 帰結

- 名乗りは登録のときに行うので、分類を足したら導入をやり直す必要がある。
- 実装していない能力を名乗ると、TSF はその口を呼びに来て失敗する。
  分類を足すときは、対応する実装があることを確かめる。
- **「出ない」の原因が実装ではなく宣言にあることがある。** 実装を三度
  直しても症状が変わらないときは、実装の外を見る。今回は「別の場面で
  選べない」という無関係に見えた報告が鍵になった。症状を一つだけ見て
  いると、こういう共通の原因に気づけない。
