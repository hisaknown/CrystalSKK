# ADR-0016: 辞書は一つのプロセスだけが持つ

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0001, ADR-0014, PRD §7, PRD Q-04

## 背景

TIP は入力先アプリのプロセスの中で動く。辞書をそこで読むということは、

- **Word にも Chrome にも写しが一つずつ載る** (4.28 MiB, 見出し 175,790 件)
- 隔離されたアプリからはファイルに触れず、触れるようにすれば**機械中の
  サンドボックスアプリに利用者の辞書を開いて回る**ことになる (ADR-0014)
- ユーザー辞書の書き手が数えきれない。**同時に書けば学習は壊れる**

PRD §7 が最初から分離を掲げていたのはこのためだった。

## 決定

**辞書を持つのは `crystalskk-server` だけにする。** TIP は名前付きパイプ越しに
頼む。

語彙は `crystalskk-ipc` に分けた。パイプも Windows も出てこない純粋な crate で、
**運び方を変えても語彙は動かない**。試験も普通に書ける。

継ぎ目は新しく作っていない。ADR-0001 で切った `CandidateSource` がそのまま
境界になった。**エンジンは、辞書がパイプの向こうにいることを知らない。**

## 逃げ道は作らない

繋がらなかったときに TIP が自分で辞書を読む道は**用意しない**。

一度はそれを提案したが、**分離する理由を自分で壊していた**。読み手が二つに
なれば書き手も二つになる。加えて、めったに通らない道は腐る。半年後にサーバが
落ちたとき、その道が動く保証はない。

CorvusSKK も同じで、`imcrvtip/` には辞書を読む処理が一行も無い。繋がらなければ
候補は空のまま返る。

代わりに**居ない場面を起きにくくする**。

- 導入がその場で起こす
- ログオンのたびに起きるよう登録する (利用者ごとの `Run`)
- 引く直前に、居なければ起こす

そのうえで、**繋がらないことは隠さない**。候補が空なのを「辞書に無い」と
思わせず、窓に `[辞書に繋がりません]` と出す。ここは CorvusSKK より一歩
足している。向こうは候補が空になるだけで、**辞書に無い語とサーバの不在が
利用者から見分けられない**。

## 入れ替えるときは、落とさずに頼む

サーバはユーザー辞書の唯一の書き手である。落とせば書きかけの学習が消える。

1. 終わってくれと頼む (`exit`)
2. 消えるのを待つ
3. 新しいものを置く
4. 起こす

消えてくれなくても構わない。動いている実行ファイルは上書きできないが**改名は
できる**ので、DLL と同じ手で退ける。

## パイプに与える許可 (Q-04)

辞書のファイルで学んだことが、そのままカーネルオブジェクトにも出てくる。
隔離された入れ物の中の TIP から届かなければ、ストアアプリで変換できない。

- `AC` と `S-1-15-2-2` に**読み書きと同期だけ**を与える。すべては与えない。
  許可そのものを書き換える権利まで渡す理由がない
- `S:(ML;;NW;;;LW)` を付ける。隔離された入れ物は低い整合性で動くので、
  これが無いと書き込めない
- 名前に利用者の SID を入れる。**同じ機械の別の利用者と待ち合わせ場所を
  共有しない**

## 帰結

- ユーザー辞書の書き手は一つになった。PRD §7 が挙げた分離の理由のうち、
  三つ (メモリ、AppContainer、単一書き手) がこれで満たされる。
- **隔離されたアプリでも学習が残るようになった。** ADR-0014 で「サーバが
  できるまでの妥協」としていた点が解けた。辞書ファイルへの読み許可も、
  本来は要らなくなる (まだ外していない)。
- 答えを書いたら `FlushFileBuffers` を呼ぶ。**呼ばずに切ると、相手が読む前に
  捨てられる。** 単体試験は通るのに実機で間々落ちる、という形で出た。
- 依存の向きのために `paths` を TIP からサーバへ移した。辞書の置き場所を
  知っているべきは、辞書を持つ側である。
