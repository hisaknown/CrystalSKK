# ADR-0041: 小窓は窓の GDI の画面に Direct2D で描く

- ステータス: Accepted
- 日付: 2026-09-26
- 関連: ADR-0035, ADR-0014

## 背景

候補の窓とモードの窓は、Direct2D の窓に直接描く描く先
(`CreateHwndRenderTarget`) で描いていた (ADR-0035)。

ストアアプリ (Microsoft Store) の中では、窓は出るのに中身が白いままだった。
描く先を作るところで `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE` が返っていた。
GPU を使う描く先 (`DEFAULT`) だけでなく、CPU で描く描く先 (`SOFTWARE`) でも
同じだった。窓に直接描く描く先は、どちらでも裏で DXGI の画面を作る。
隔離された入れ物の中では、それ自体が断られているとみられる。なぜ断られるのか
までは突き止めていない。

同じ報告は見つからなかった。代わりに、ほかの IME は窓に直接描く描く先を
使っていないことが分かった。

- CorvusSKK: `CreateDCRenderTarget` を `WM_PAINT` の HDC に結びつけて描く。
  透かさない。
- Weasel (Rime): `CreateDCRenderTarget` でメモリ上の画面に描き、重ね窓
  (`UpdateLayeredWindow`) で画素ごとの透け具合を付ける。また、既定の描く先が
  アプリごとに GPU のドライバを読み込み、最初の打鍵が数百 ms 遅れるとして、
  CPU で描くように変える案が出ている (rime/weasel#1913)。

## 選択肢

### A. GDI の画面に描き、透かしをやめる (CorvusSKK と同じ)

- 利点: 一本の経路。確実に動く。
- 欠点: ADR-0035 の Acrylic を失う。

### B. 重ね窓で画素ごとの透け具合を付ける (Weasel と同じ)

- 利点: 半透明にできる。
- 欠点: DWM のぼかしは効かない。角の丸みも影も自前になり、ADR-0035 の
  「窓の形は DWM に任せる」から大きく戻る。

### C. 窓に直接描く描く先を先に試し、断られたら GDI の画面に描いて透かしを切る

- 利点: ふつうのアプリの見た目は変わらない。
- 欠点: 経路が二本。ストアアプリでだけ見た目が変わる。対症療法である。

### D. GDI の画面に描き、DWM の透かしはそのまま頼む

- 利点: 一本の経路のまま、見た目を保てる。
- 欠点: GDI の画面を通したときに、透け具合 (アルファ) が DWM まで正しく届く
  かどうか、試すまで分からなかった。

## 決定

**D を採る。** 試したところ、ストアアプリでもふつうのアプリでも、中身が
描かれ、地も今までどおり透けた。

- 描く先は `CreateDCRenderTarget` で作り、**スレッドに一つ**持つ。描くたびに
  窓の HDC を借りて結びつけ直し (`BindDC`)、描き終えたら返す。
- 形式は `B8G8R8A8` のアルファ付き (premultiplied)。DWM の透かし
  (ADR-0035) はこれまでどおり頼む。
- **CPU で描く** (`SOFTWARE`)。小窓には十分で、アプリごとに GPU のドライバを
  読み込む遅れも避けられる。
- 描く命令 (Direct2D と DirectWrite) は変えない。変わるのは、描き上がった絵を
  窓へ渡す最後の一段だけである。
- 描き終えられなければ描く先を捨て、次に作り直す。

## 帰結

- 窓ごとの描く先が無くなり、窓を壊すときに捨てる手間も無くなった。
- 描く先を作れない・描き終えられないときは、理由を記録する。以前は黙って
  いたので、白い窓の原因が分からなかった。
- 見直す条件: GDI の画面を通したときに、透け具合が DWM に届かない環境が
  見つかったとき。そのときは A か B を考える。
