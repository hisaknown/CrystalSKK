# ADR-0039: 確定と改行を一度にするときは、確定を書いてから同じキーを送り直す

- ステータス: Accepted
- 日付: 2026-09-26
- 関連: ADR-0038, ADR-0008

## 背景

ddskk の既定 (`skk-egg-like-newline` が nil) では、▽ や ▼ で RET を押すと
確定して改行も入る。CrystalSKK の `kakutei` は確定だけで、CorvusSKK と同じ
である。どちらも選べるように、`kakutei_newline` という操作を足したい
(ADR-0038)。そうすれば、Enter をどちらに割り当てるかで流儀を選べる。

TSF は打鍵を二度尋ねる。`OnTestKeyDown` で「食べるか」を聞き、食べると
答えたときだけ `OnKeyDown` を呼ぶ。`OnKeyDown` が食べなかったと答えれば、
キーはアプリへ届く。CorvusSKK は二つの答えを常に揃えていて、「確定して
渡す」の前例は無い。

## 選択肢

### A. 確定の文字列に改行を混ぜる

- 利点: 答えが揃う。
- 欠点: 文字としての改行と、Enter キーは違う。一行の入力欄では送信が
  起きず、改行が文字として入るか捨てられる。アプリによっては CR と LF の
  扱いも違う。

### B. 打鍵を食べ、確定してから Enter を送り直す (`SendInput`)

- 利点: 答えが揃う。アプリには本物の Enter が届く。
- 欠点: 送り直した Enter はまたこちらを通る。修飾キーの状態との食い違い、
  UIPI で送れない窓、ほかの打鍵との順序の入れ替わりが起きうる。

### C. `OnTestKeyDown` では食べると答え、`OnKeyDown` で確定を書いてから食べなかったと答える

- 利点: キーはアプリが受け取った本物のまま。送り直しも無い。確定は
  `OnKeyDown` の中の同期の編集セッションで書くので、アプリが Enter を
  処理する前に文書に入っている。
- 欠点: 二つの答えが食い違う。TSF の文書は `OnKeyDown` の答えで決まると
  読めるが、`ITfKeystrokeMgr::TestKeyDown` の答えを見て自分で振る舞いを
  決めるアプリがあるかもしれない。

## 決定

**B を採る。** 初めは C を試したが、Firefox で崩れた (下の「試した結果」)。

- エンジンの応答に `pass_through` を足す。「処理したうえで、キーもアプリへ
  渡す」の印で、`handled` とは別に持つ。エンジンとしては処理しているので、
  `would_handle` と `press` の一致 (試験で守っている) はそのまま保つ。
- TIP は打鍵をいつもどおり食べ、確定を書いたあとで、`pass_through` が
  立っていれば同じ仮想キーを `SendInput` で送り直す。修飾キーは押された
  ままなので、送るのは押し下げと離しだけでよい。`OnTestKeyDown` と
  `OnKeyDown` の答えは揃ったままになる。
- 送り直したキーはもう一度こちらを通る。そのときには確定が済んでいて
  何も残っていないので、エンジンに渡しても素通しになる。**それでも念のため、
  送り直した打鍵には印 (`dwExtraInfo`) を付け、印があれば何も見ずに渡す。**
  食べてしまうと、確定のたびに同じキーが回り続ける。
- 確定するものが無ければ `kakutei_newline` は何もしないので、初めから
  食べない (ADR-0038)。
- 辞書登録の中では渡さない。確定した語は登録の欄に入るもので、文書へ
  改行を送る場面ではない。

## 試した結果

C は、メモ帳では確定して改行が入った。Firefox では、検索欄で Enter が送信に
ならず、複数行の欄でも改行が入らなかった。Firefox は `OnTestKeyDown` の答えを
見て、食べると言われたキーを自分で捨てていると考えられる。`OnKeyDown` で
食べなかったと答えても遅い。

B に替えたあとは、メモ帳でも Firefox の検索欄と複数行の欄でも、確定して
改行 (送信) が入った。

## まだ確かめていないこと

次のアプリで、▽ と ▼ のそれぞれから Enter を押し、確定した語の後ろに
改行が一つだけ入るか (二重にならないか、語が消えないか) を見る。

- メモ帳
- ブラウザ (Edge) の複数行の欄と、一行の欄 (検索欄など、Enter で送信するもの)
- Word
- Windows Terminal
- エクスプローラーの名前の変更 (Enter で決定するもの)

B の欠点として挙げたこと (修飾キーとの食い違い、順序の入れ替わり) も、
ここで見る。

## 帰結

- Enter を `kakutei_newline` へ移すだけで ddskk の流儀になる。
- **雛形の Enter は `kakutei` のままにする。ここは ddskk の既定から外れる。**
  確定と一緒に改行や送信まで起きるのは、Windows の IME としては踏み込み
  すぎである。確定だけのほうが Windows の IME らしく、CorvusSKK とも同じで、
  送り直しの副作用も起きない。欲しい人は設定で Enter を移せばよい。
- 同じ仕組みで、ddskk どおりに「▼ で矢印を押したら確定してカーソルを
  動かす」も作れる。
