# ADR-0005: 打ち間違いの救済は、入力が矛盾するときだけ行う

- ステータス: Accepted
- 日付: 2026-09-22
- 関連: PRD §3 (設計原則 5) / PRD §5.1 F-07 / ADR-0001

## 背景

SKK ではシフトの位置が語の区切りを決めるため、シフトを押す位置を取り違える
打ち間違いが起きる。実際に次の四つが挙がった。

| 打鍵 | 意図 | 打鍵列から読み取れること |
|---|---|---|
| `kAyoU` | `KayoU` | `k` は単独ではかなにならない |
| `KAyoU` | `KayoU` | 見出し語にかながない位置で送り仮名は始まれない |
| `Okuri` | `OkuRi` | `おくり` は送りなしの見出し語として正しい |
| `KAYOU` | `KayoU` | `かy` は送りありの辞書キーとして正しい |

前の二つは救済を実装した。後の二つをどうするかを決める必要がある。
どちらも「辞書を引いて見つからなかったら、別の解釈で引き直す」という
仕組みで救える。先行実装では SKKFEP が「SKKプラス」としてこれを持っている。

## 選択肢

### A. 引き直しを実装する

送りなしで失敗したら末尾のかなを送り仮名とみなして引き直す、送り仮名の位置を
ずらして引き直す、など。

- 利点: 四つすべてを救える。打ち間違いに強くなる。
- 欠点: 引き直しの根拠が「辞書に無いこと」しかない。だが辞書に無いことは
  打ち間違いの証拠ではなく、**辞書登録が始まる条件そのもの**である。新語を
  登録しようとするたびに、勝手な引き直しが挟まることになる。

### B. 入力が矛盾するときだけ救う

打たれた打鍵列をそのまま解釈すると成り立たない場合に限って救済する。
辞書の内容は根拠にしない。

- 利点: 救済の根拠が打鍵列の中で完結する。辞書登録の邪魔をしない。
  救済が働いたかどうかを利用者が打鍵から予測できる。
- 欠点: `Okuri` と `KAYOU` は救えない。

## 決定

**B を採る。** 救済の根拠は打鍵列そのものに限り、**辞書に無いことを打ち間違いの
証拠として使わない**。

`Okuri` は送りなしの見出し語として完全に正しい入力であり (`おくり` は
SKK-JISYO.L にも載っている)、これを疑うことは正しい入力を否定することになる。
`KAYOU` はすべてのシフトが押されているため、打鍵列が区切りの情報を持っていない。
どちらも推測でしか救えず、推測は PRD §3 の「SKK の驚きのなさを守る」に反する。

救済が働く条件は、次のように打鍵列だけで説明できる。

- 単独でかなにならない打鍵は、捨てずに次と組み合わせる
- 新しい区切りを作れない位置のシフトは、区切りを作らない

## 帰結

- 打ち間違いの救済は、辞書を引く前に完結する。`CandidateSource` は
  「打ち間違いかもしれない」という文脈を知らなくてよい。
- 救済が働いたかどうかは辞書の内容に左右されない。同じ打鍵は、辞書が変わっても
  同じ見出し語になる。
- `Okuri` と `KAYOU` は救われない。前者は正しい入力として扱われ、後者は
  辞書登録に入る。これは意図した挙動である。
- **この決定は「引き直しを一切しない」ではない。** 打鍵列の外に根拠がある
  引き直し、たとえば利用者が明示的に要求する操作や、文脈を使った候補の
  並び替え (ADR-0001 の `Ranker`) は別の話として扱える。禁じているのは
  「辞書に無いこと」を根拠に解釈を変えることだけである。
