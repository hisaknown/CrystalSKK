# ADR-0038: キーは名前の付いた操作に割り当て、状態による意味の違いはエンジンが持つ

- ステータス: Accepted
- 日付: 2026-09-26
- 関連: PRD F-14, ADR-0020, ADR-0012

## 背景

キーはエンジン (`engine.rs`) と TIP (`preserved.rs`) に直に書いてあった。
`Ctrl+J`・`Ctrl+G`・`q`・`l`・`/`・`x`・`X`・`>`・Tab、そして入切の
半角/全角などである。利用者が変えられるようにする (PRD F-14)。

ADR-0020 は形を先送りしていた。**同じキーでも状態によって意味が違う**
(`q` は直接入力ではカタカナへの切り替え、見出し語入力ではカタカナでの確定)
ので、一つのキーに一つの値を割り当てる形では済まない。

入切のキーは TSF の横取りキーで、エンジンを通らない。文字にならない
キー (半角/全角、IME 専用のキー、F1 など) も書けなければならない。

## 選択肢

### A. 操作に名前を付け、操作ごとにキーの一覧を割り当てる

`kakutei = ["Ctrl+J"]` のように書く。状態による違いはエンジンが解釈する。
ddskk の `skk-kakutei-key` や `skk-previous-candidate-char` と同じ考え方。

- 利点: 短い。ddskk を知っている人には馴染む。状態の組み合わせを利用者が
  考えなくてよい。
- 欠点: 「見出し語入力のときだけ別のキーにする」はできない。

### B. 状態ごとに、キーから操作への表を書く

`[keys.direct]`・`[keys.composing]`・`[keys.selecting]` に分ける。

- 利点: 自由度が高い。
- 欠点: 長い。同じことを何か所にも書くことになり、書き漏れると状態に
  よって効いたり効かなかったりする。状態の区別は内部の事情である。

## 決定

**A を採る。** 利用者の選択でもある。

### 変換の操作

`[keys]` に 16 の操作を置く。`kakutei`・`hiragana`・`cancel`・
`delete_backward`・`start_henkan`・`previous_candidate`・`purge`・
`toggle_kana`・`half_katakana`・`ascii`・`full_ascii`・`abbrev`・
`set_henkan_point`・`complete`・`take_completion`・`affix`。

- 値はキーの名前の配列。幾つ並べてもよく、`[]` ならその操作は使わない。
- **一つのキーは一つの操作にしか割り当てられない。** 重なれば、両方の名前を
  挙げて読むのを断る。黙ってどちらかを勝たせると、片方が効かない理由が
  利用者に分からない。
- キーは `"Ctrl+J"` と書く (利用者の選択。Windows の画面の書き方)。書けるのは
  エンジンが受け取れるものだけで、一文字、`Ctrl+` と英字、`Space`・`Tab`・
  `Enter`・`Backspace`・`Escape`・`Up`・`Down`。英字の大文字はシフト付きの
  打鍵である (`"X"`)。
- `completion.take_key` は `keys.take_completion` に移した。補完の窓に出す
  キーは、そこに並べた最初の文字のキーである。

**Enter・Backspace・Escape も特別扱いしない。** 雛形でそれぞれ `kakutei`・
`delete_backward`・`cancel` に並べてあるだけである。CorvusSKK も同じで、
Enter は Ctrl+M と並ぶ「確定」のキーの一つにすぎない。

- Ctrl+J と Enter は、直接入力での働きが違う。Ctrl+J は英数やカタカナからも
  ひらがなへ戻すが、Enter は入力モードを変えない。Enter を Ctrl+J と同じ操作に
  すると、英数モードの Enter がかなへ戻って改行も入らなくなる。そこで二つに
  分けた。`kakutei` (Enter) は確定だけ、`hiragana` (Ctrl+J) は確定して
  ひらがなへ戻る。CorvusSKK も「確定」と「ひらがなモード」を分けている。
- **上下の矢印は SKK の操作に使わない。** これまでは候補選択で前後の候補に
  していたが、これは CorvusSKK の流儀である。ddskk では、▼ で矢印を押すと
  確定してからカーソルが動く。どちらにしても SKK に要る操作ではないので、
  割り当ての無いキーとして扱う。使いたければ `previous_candidate` などに並べ
  られる。

**未確定が何も無いときに何もしない操作は、打鍵を食べない。** アプリへ渡す。
取り消すものの無い `cancel` や、確定するものの無い `kakutei` がそうである。
ただし `hiragana` は、すでにひらがなで打ちかけが無くても食べる。**行き先の
決まった切り替えは冪等にする。** 押せばいつも同じになる操作で、キーがアプリへ
漏れるかどうかがいまのモードで変わると、同じキーの意味が読めなくなる。
これまで直接入力の Ctrl+G は
何もしなくても食べていたが、それをやめた。一方で、未確定があるあいだ (▽・▼・
辞書登録) は、何も起きなくても食べる。アプリへ渡すと、未確定を残したまま
文書が動いてしまう。候補の無いラベルキーや、確かめているあいだの y/n 以外の
キーがそうである。

割り当てないもの。

- シフトで見出し語や送り仮名を始めること。SKK の根幹で、キーではなく
  「大文字で打つ」ことに意味がある。
- 候補の一覧から選ぶキー (`candidates.labels`) と、消してよいかの y/n。

ローマ字の打ちかけの続きになる文字は、これまでどおり割り当てより先に
ローマ字として読む (`z/` で `・`)。

**文字のキーがローマ字の規則とぶつかっても断らない。** 操作が働く場面では、
その文字はローマ字として読まれない。小文字ならその文字で始まる規則が打てず、
大文字ならその文字で見出し語や送り仮名を始められない。使わない規則の頭文字を
操作に回すのは意図してのことでもありうるので、知らせるだけにする。知らせるのは
**トレイの「設定を読み直す」のときだけ**で、読み直しの知らせに添える。利用者が
設定を書き換えた直後に自分で起こす操作なので気づけるし、ふだんは邪魔をしない。
「一度だけ知らせる」には知らせたことを覚えておく必要があり、その割に得るものが
少ない。候補選択の中でしか働かない操作 (`previous_candidate`・`purge`) と、
補完候補が出ているときだけ働く `take_completion` はぶつからない。

変換を空白以外に割り当てたときは、見出し語入力での空白は見出し語の一文字に
なり、候補選択での空白は暗黙の確定をしてから空白を打つ。

### 入切の操作

同じ `[keys]` に `on_off` (入切を兼ねる)・`on`・`off` を置く。

- `"半角/全角"`・`"ImeOn"`・`"ImeOff"`・`"F1"`〜`"F24"`・`"Space"`・一文字に、
  `Ctrl+`・`Shift+`・`Alt+` を付けて書ける。
- 半角/全角と IME 専用のキーは、これまでどおり修飾を問わずに拾う。修飾を書けば
  誤りとする。
- **修飾の無い文字や空白は書けない。** 横取りすれば、その文字が打てなくなる。
- **入にするキーが一つも無ければ読むのを断る。** 切られたアプリで二度と
  入にできなくなる。
- 文字のキーは、TIP が登録するときにいまの配列で仮想キーを引く。その文字に
  シフトが要る配列なら、シフトも修飾に足す。
- 設定を受け取るまでは何も登録しない。受け取るまではエンジンも動かない
  (ADR-0020)。受け取った設定で入切のキーが変わっていれば、いまの状態のまま
  登録し直す。

## 帰結

- 雛形のキーはほぼこれまでどおりである。振る舞いが変わるのは二つ。直接入力で
  何も打ちかけていないときの Ctrl+G がアプリへ届くようになった。上下の矢印で
  候補を送れなくなった。
- Enter で確定と改行を両方する流儀 (ddskk の既定、`skk-egg-like-newline` が
  nil) は、`kakutei_newline` のような操作として足せば、Enter の割り当てを変える
  だけで選べる。ただし「確定したうえでキーをアプリへ渡す」を TSF で作れるかを
  先に確かめる必要があり、ここでは入れない。
- 前の版の設定ファイルには `[keys]` が無いので、節ごと書き足される
  (ADR-0020)。`completion.take_key` を変えていた人は、それが知らない項目
  として知らされるので、`keys.take_completion` へ移す必要がある。
- `would_handle` と `press` の一致は、割り当てを大きく変えた表でも長い打鍵の
  列で確かめている。操作を足すときは、両方に書く。
- 見直す条件: 状態ごとに違うキーを求められたとき。そのときは B の表を A の
  上に重ねられる (操作の名前はそのまま使える)。
