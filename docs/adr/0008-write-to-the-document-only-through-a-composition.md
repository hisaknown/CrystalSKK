# ADR-0008: 文書への書き込みは必ず composition を通す

- ステータス: Accepted
- 日付: 2026-09-22
- 関連: PRD §3 (ホストアプリを巻き込まない) / ADR-0002

## 背景

確定した文字列を文書へ入れる方法は、TSF の見た目には複数ある。

1. `ITfInsertAtSelection::InsertTextAtSelection` に `TF_IAS_NOQUERY` を渡して直接入れる
2. 選択範囲を取り、その `ITfRange::SetText` で置き換える
3. composition を開き、その範囲へ書いてから閉じる

未確定の表示 (`▽` `▼`) がまだない段階では、1 が最も短い。実際にそう書いた。
**メモ帳がその呼び出しの中で落ちた。** 記録は編集セッションに入ったところで
途切れ、パニックは記録されていない。呼んだ先でのアクセス違反である。

2 に替えても、それが安全である根拠はなかった。誰もその書き方をしていない。

先行実装を読んだ。CorvusSKK は、**確定した文字列であっても必ず composition を
開き、その中へ書いてから閉じている**。`TF_IAS_NOQUERY` は使わず、
`TF_IAS_QUERYONLY` で「書き込む場所」だけを受け取り、そこに composition を
開く。書く前には、選択範囲が composition の内側にあることを確かめている。

## 決定

**文書へ書くのは composition の中だけにする。** 確定した文字列も例外にしない。

手順は CorvusSKK に倣う。

1. `TF_IAS_QUERYONLY` で書き込む場所の範囲を受け取る
2. その範囲に composition を開く
3. composition の範囲へ文字列を書く
4. 選択を composition の末尾へ動かす
5. composition を閉じる

書く前に、選択範囲が composition に覆われているかを確かめる。覆われて
いなければ書かない。アプリがカーソルを動かした後に書くと、関係のない場所を
壊すため。

## 帰結

- 確定だけのいまの段階では、composition を開いてすぐ閉じることになる。
  一見無駄だが、**TSF にとって入力方式が文書へ書く手段はこれしかない**と
  考えるのが正しい。短い道は用意されているように見えて、通れない。
- 未確定の表示を実装するときは、composition を開いたまま保つだけでよい。
  手順を変えずに済む。
- `ITfCompositionSink` を実装する必要がある。アプリが composition を
  外から終わらせたとき (`OnCompositionTerminated`) に、入力の途中経過を
  捨てるため。
- **短く書ける道が落ちたときは、動いている実装を読むこと。** この件は
  半日を推測に使った。CorvusSKK は MIT ではないが、こうした「決まりきった
  作法」については読んで学んでよい。
