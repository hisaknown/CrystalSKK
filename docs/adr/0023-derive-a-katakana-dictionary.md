# ADR-0023: カタカナ語の辞書を、元の辞書から読み込むときに作る

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0022, ADR-0021

## 背景

SKK にはカタカナ語の辞書が無い。L 辞書にはカタカナ語が大量に載っている
が、**自分の読みの見出しの下に無いことが多い**。手元の L 辞書で確かめると、
`ヴァイオリン` は `violin` (abbrev 用の英字の見出し) の下にしか無く、
`う゛ぁいおりん` と打っても出てこない。

SKKFEP では、L 辞書からカタカナ語の辞書を作るスクリプト
(`skkdict_kana.js`) を回して、その結果を辞書に足している。

あわせて、見出しの `ヴ` の書き方が食い違っていた。SKK の辞書はひらがなの
`ヴ` を `う゛` (う + 濁点) と書く (`ぐるーう゛かん /グルーヴ感/`)。ところが
CrystalSKK の雛形のローマ字テーブルは、ひらがなでも `vu` → `ヴ` にしていて、
▽ で打った見出しが辞書と一致しなかった。

## 決定

### 規則はスクリプトに合わせる

`crystalskk_dict::derive::katakana_words` が、辞書の本文からカタカナ語の辞書の
本文を作る。

- 候補の語 (`;` より前) が 2 文字以上で、すべて `ァ`〜`ー` の範囲にあるものを
  拾う。送りあり・送りなしは問わない。
- 注釈も含めて `?` のある候補は拾わない (辞書で「自信が無い」とされたもの)。
- 見出しは**その語自身の読み**にする。`ァ`〜`ン` はひらがなに、`ヴ` は `う゛` に
  し、`ー` `・` `ヵ` `ヶ` などはそのまま。読みが語と変わらないものは拾わない。
- 同じ見出しには候補を一つだけ置く。注釈違いで同じ語が何度も出るときは、
  長いほう (注釈の詳しいほう) を残す。

手元の L 辞書からは 26,520 語ができる。

### スクリプトではなく、読み込むときに作る

`config.toml` の辞書の並びに書く。

```toml
sources = [
    "https://…/SKK-JISYO.L",
    { katakana_from = "https://…/SKK-JISYO.L" },
]
```

- **作り直す手間が無い。** 元の辞書が更新されれば、読み直すときに一緒に作り
  直される。スクリプトなら、更新のたびに回し直すことになる。
- **どの辞書から何を作っているかが、設定ファイルに見える** (ADR-0020)。手元に
  出どころの分からない生成物が残らない。
- 元の辞書と同じファイルを読むので、並びに両方あっても**取得も読み込みも
  一度で済む**。抜き出しは読み込みの一部として一瞬で終わる。
- 生成物は利用者の手元で作られるだけで、配布しない。元の辞書の使用許諾は
  そのまま元の辞書のもの。

雛形の並びにも入れる。L 辞書の後ろに置くので、L 辞書で引ける語の並びは
変わらず、L 辞書で引けなかった読みだけが増える。

知らない派生の書き方 (`{ hiragana_from = … }` など) は、推し量らずに断る。

### ヴ は う゛ と書く

- 雛形のローマ字テーブルの `va` `vi` `vu` `ve` `vo` を `う゛ぁ` … `う゛ぉ` にした。
  ddskk と同じく、ひらがなでは `う゛`、カタカナでは `ヴ` になる。
- `to_katakana` は `う゛` (独立した濁点 U+309B でも、合成用の U+3099 でも) を
  `ヴ` にまとめる。一字ずつ写すと `ウ゛` になってしまう。
- ローマ字テーブルは利用者の持ち物なので (ADR-0021)、すでに作られた
  `romaji.txt` は書き換えない。

## 帰結

- 並び順どおり、L 辞書の候補が先、派生した辞書の候補が後に出る。派生した
  辞書を上に置けば、カタカナ語が先に出る。
- `q` でカタカナにした語を覚える規則 (候補として辞書にあるときだけ) にも
  効く。カタカナ語が読みの候補として揃うので、覚えられる語が増える。
- 既存の利用者は、雛形の変更を自分で取り込む必要がある。`config.toml` の
  `sources` はすでにあるので書き足されない。`romaji.txt` も書き換えない。
- 見直す条件: 別の派生 (たとえば英字の見出しだけを抜いた辞書) が要るとき。
  書き方 `{ <派生>_from = … }` は、そのまま広げられる。
