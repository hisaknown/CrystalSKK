# ADR-0020: 設定ファイルに書かれていることを、効いている設定のすべてにする

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: PRD F-14, ADR-0016, ADR-0019

## 背景

補完の文字数、候補のラベル、一覧に移るまでの回数などを、エンジンの定数と
して持っていた。利用者が変えられるようにする (PRD F-14 `config.toml`)。

利用者の意図は次のとおり。

- **既定値というものを持たない。** 効いている値は、すべて利用者の設定
  ファイルに書かれている。利用者の知らないところに設定が生えることを
  許さない。
- 同梱の雛形を持つのはよい。ただし**実行時の既定値として参照しない**。
  使うのは、初めてファイルを作るときと、足りない項目を書き足すときだけ。

問題は、**新しい版で項目が増えたとき**である。利用者のファイルにはその
項目が無い。

## 選択肢

### A. 同梱の `default.toml` の上に、利用者のファイルを重ねる

利用者は変えたい項目だけを書き、書かなかった項目は同梱の値で効く。

- 利点: 利用者のファイルに触れずに済む。
- 欠点: **書いていない値が効く。** 利用者の知らないところに設定が生える。
  意図に反する。

### B. 足りなければ動かない

足りない項目を挙げて、設定を読むのを拒む。ファイルには触れない。

- 利点: ファイルに書かれていない値は決して効かない。
- 欠点: 更新のたびに設定の誤りで止まる。止まっている間の振る舞いにまた
  「見えない値」が要る。

### C. 足りない項目を、利用者のファイルに書き足してから使う

雛形から足りない項目だけを利用者のファイルへ追記し、注記を添える。
読むのは常にファイルそのもの。

- 利点: 設定が生えるとすれば、**必ず利用者のファイルの中**になる。
  更新で止まらない。項目を消せば、雛形の値で書き戻される。
- 欠点: 利用者のファイルを書き換える。書式を崩せば嫌われる。

## 決定

**C を採る。**

### ファイルの扱い

- 雛形 `crates/crystalskk-settings/default.toml` をバイナリに埋め込む。全項目を
  説明付きで書く。
- ファイルが無ければ、雛形をそのまま書き出す。
- 足りない項目は `toml_edit` で**その節の中に**書き足す。雛形の説明と、
  `# CrystalSKK <版> で書き足しました` の注記を添える。利用者のコメントや
  並び、改行の流儀 (CRLF) は崩さない。
- 知らない項目は消さずに知らせる。打ち間違いか廃止された項目かは、
  利用者にしか分からない。
- 読むとき (`crystalskk_settings::parse`) は雛形を見ない。足りなければ誤り。

### 既定値を持たないことを、仕組みで守る

- エンジンの `Options` は `Default` を実装しない。
- エンジンは `configure` で値を受け取るまで**何もしない**。打鍵はすべて
  アプリへ素通しになる。
- 「雛形がそのまま読める」ことを試験で確かめる。項目を足して雛形に
  書き忘れれば、そこで落ちる。

### 誰が読み、誰が書くか

- **読んで書き足すのは辞書サーバだけ。** 書き手を一つに絞るため
  (ADR-0016 と同じ理由)。隔離された入れ物の中の TIP からは、そもそも
  ファイルが読めない。
- TIP は `settings` を頼み、**ファイルの全文**を受け取って同じ crate で読む。
  値に崩して運び直さないので、読み方が一つで済む。
- TIP は有効化されたときと、入力先に焦点が入ったときに尋ね直す。
  **書き換えた設定は、入力先を切り替えたときに効く。**
- 受け取れなかったときは、前に受け取った値のまま続け、候補の窓で理由を
  言う。一度も受け取れていなければエンジンは動かない。
- 導入 (`crystalskk-setup install`) でも、本人として動いている段階で同じ
  書き足しを行い、**何を書き足したかを画面に出す**。サーバには知らせる
  相手がいない。
- CLI は自分の `crystalskk-config.toml` を同じ読み方で使う。

置き場所は辞書と並べて `%LOCALAPPDATA%\CrystalSKK\config.toml`。

### 最初の項目

| 項目 | 意味 |
|---|---|
| `completion.dynamic` | 動的補完を出すか (Tab の補完は切れない) |
| `completion.min_length` | 補完を始める見出し語の長さ |
| `completion.limit` | 覚えておく補完候補の数 |
| `completion.take_key` | 補完候補を受け取り、変換して確定するキー |
| `completion.show_reading` | 補完の窓に読みも添えるか |
| `candidates.until_list` | 何回目の変換から一覧にするか |
| `candidates.labels` | 一覧から選ぶキー。この数が一ページの候補数 |

キーバインドの全体はまだ入れていない。一つのキーに一つの値を割り当てる
形では済まず (モードごと、状態ごとに意味が違う)、別に形を決める。

## 帰結

- 項目を足すときは、雛形に書き、`parse` に一行足せばよい。書き足しは
  自動で起きる。
- 設定ファイルを壊すと、直すまで日本語の入力ができない (前に受け取った
  値があれば、それで続く)。理由は候補の窓とログに出る。
- 利用者のファイルは版を上げるたびに少しずつ伸びる。注記で経緯が
  追えるので、要らなくなった注記は利用者が消せばよい。消しても書き戻さない
  (注記は項目ではない)。
- 見直す条件: 設定 GUI (F-16) を作るとき。GUI も同じ crate で読み書き
  すれば、この決定はそのまま使える。
