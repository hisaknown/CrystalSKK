# ADR-0027: 候補の注釈は窓にだけ出す

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0015, ADR-0020, ADR-0026, PRD F-13

## 背景

SKK の辞書は、候補の `;` より後ろに注釈を持てる (`/橋;bridge/`)。辞書は注釈を
読んでいたが、TIP はどこにも出していなかった (CLI だけが出していた)。

注釈は**しばしばとても長い**。入力欄に出すと、打っている場所で長い文が伸び
縮みしてうっとうしい。

## 決定

**注釈は窓にだけ出す。入力欄 (未確定の文字列) には出さない。**

- **候補を一つずつ見せているあいだ** (一覧に移る前、`▼橋` のとき): 注釈が
  あれば、**注釈だけの窓**を出す。窓の幅 (100% で 360 画素) で折り返して、
  全文を出す。注釈が無ければ窓は出さない。
- **一覧を出しているあいだ:** 各候補の右に、注釈を薄い色 (文字の色と地の色の
  中間) で添える。一覧の窓が長い注釈で画面いっぱいに広がっては候補が読め
  ないので、240 画素で切り、はみ出す分は「…」にする。
- 設定の `[candidates] show_annotation` で切れる (ADR-0020)。雛形は出す。

注釈だけの窓はシステムの候補一覧 (`ITfCandidateListUIElement`) には差し出さ
ない。一覧ではなく、一つずつ見せている候補に添えるものだからである。アプリが
候補一覧を自分で描くと言った場合 (ADR-0015)、一覧の注釈はそのアプリの描き方
次第になる。システムの候補一覧には注釈を渡す口が無い。

## 帰結

- 注釈を読みたければ、一つずつ見せている段階なら全文が読める。一覧では
  切れることがあるが、`x` で戻れば一つずつの段階で全文が見える。
- 窓の一行は「本文」と「注釈」の組になった。ほかの中身 (補完、辞書登録、
  知らせ) は注釈を持たない。
