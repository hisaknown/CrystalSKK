# ADR-0026: 小窓の色は明るい組と暗い組を設定に書き、アプリの明るさで選ぶ

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0015, ADR-0020, ADR-0025

## 背景

候補の窓 (ADR-0015) とカーソルのそばの入力モードの窓 (ADR-0025) は、Win32 の
システムの色 (`GetSysColor`) で描いていた。

- **Win32 のシステムの色は、ダークモードにしても白いまま変わらない。** 暗い
  アプリの上に白い窓が出る。
- 枠と選んでいる行に使う `COLOR_HIGHLIGHT` は、**「個人用設定 → 色」の
  アクセントカラーに追従しない**。多くの環境で青に固定である。

利用者は、ダークテーマでは黒い地にしたい、枠の色も含めて設定で選びたい、と
言った。

## 決定

色を `config.toml` に書く。既定値は持たない (ADR-0020) ので、雛形にすべての色を
書く。

```toml
[colors]
theme = "auto"      # "auto" / "light" / "dark"

[colors.light]
background = "system"
text = "system"
border = "system"
selected_background = "system"   # 選んでいる行 (反転の帯)
selected_text = "system"

[colors.dark]
background = "#2B2B2B"
text = "#FFFFFF"
border = "system"
selected_background = "system"
selected_text = "system"
```

- 色は `"#RRGGBB"` のほか、`"system"` (役目ごとの Windows の標準の色) と
  `"accent"` (Windows のアクセントカラー。`DWM\AccentColor`) で書ける。
- どちらの組を使うかは `theme` で決める。`"auto"` はアプリの明るさ
  (`AppsUseLightTheme`) に合わせる。窓が載るのはアプリの上なので、タスク
  バーの明るさ (トレイの絵が見るもの、ADR-0024) ではない。
- **ハイコントラストの配色を選んでいるときは、設定にかかわらずシステムの
  色に従う。** 利用者が選んだ配色を上書きしない。
- 雛形の値は、それまでの見た目そのままにした (明るい組はすべて標準の色、
  暗い組は地と文字だけ色で書く)。
- 色は窓を出すたびに解く。テーマを切り替えると、次に出る窓から変わる。
- 設定をまだ受け取っていないとき (設定が読めないことを知らせる窓) は、標準の
  色で描く。知らせは設定が無くても出さなければならない。

### 入れ子の節も書き足す

`[colors.light]` は入れ子の節である。設定ファイルの書き足し (ADR-0020) と
知らない項目の検出を、入れ子の節まで降りて行うようにした。入れ子の節の中の
一項目が無くても、その節の中に書き足す。

あわせて、節ごと書き足すときは**節の直前の段落だけ**を持ち込むようにした。
TOML ではファイル冒頭の説明が最初の節に付いたコメントとして読まれるので、
そのまま持ち込むとファイル全体の説明が途中に書き込まれていた。

## 帰結

- ダークモードでは、候補の窓もカーソルのそばの窓も黒い地で出る。
- アクセントカラーに揃えたければ `"accent"` と書けばよい。
- 見直す条件: Windows がダークモードの Win32 のシステムの色を用意したとき。
