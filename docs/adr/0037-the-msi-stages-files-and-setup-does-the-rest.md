# ADR-0037: MSI はファイルを置き場に置くだけにし、入れ替えと登録は crystalskk-setup が行う

- ステータス: Accepted
- 日付: 2026-09-25
- 関連: ADR-0007, ADR-0016, ADR-0031, ADR-0036

## 背景

配布用のインストーラーを MSI で作る。winget・企業での配布・「アプリと機能」
からの削除・修復に、そのまま乗れるからである。いまの導入は
`crystalskk-setup install` が行っている。

- TIP の DLL は、入力するあらゆるプロセスに読み込まれる。読み込まれた DLL は
  上書きも削除もできないが、改名はできる。`crystalskk-setup` は、使用中の
  ものを `<名前>.old-<時刻>` へ退けてから新しいものを置き、残骸は次の導入で
  片付けている。辞書サーバの exe、言語モデル、llama.cpp の DLL も同じ。
- Windows Installer は、使用中のファイルを同じパスに書こうとすると、
  「使用中のファイル」の画面を出すか、再起動したときに置き換える予約をして
  再起動を求める。自分の置いたファイルを他人に改名されると、修復や削除の
  ときに辻褄が合わなくなる。
- 版ごとのディレクトリに置いても、ぶつかる場面が残る。削除してから再起動
  しないまま同じ版を入れ直すと、削除の予約が付いた使用中のファイルと同じ
  パスに書くことになる。
- 機械全体に書く操作 (COM と入力方式の登録、`%ProgramFiles%` への配置) には
  管理者権限が要る (ADR-0007)。MSI の遅延カスタムアクションを
  `Impersonate="no"` で動かすと、LocalSystem として動く。
- 利用者ごとの操作もある。辞書サーバは利用者ごとに立ち、パイプの名前に
  利用者の SID が入る (ADR-0016)。LocalSystem からは、利用者のサーバに終了を
  頼むことも、利用者として起こすこともできない。自動起動は
  `HKEY_CURRENT_USER` の `Run` に書いており、LocalSystem が書けば
  LocalSystem の `Run` に入ってしまう。
- TIP は、辞書を引くときにサーバが居なければ自分で起こす。起こせないのは、
  隔離されたアプリ (ストアアプリなど) の中だけである。自動起動が効くのは、
  そこで最初に入力する場面に限られる。
- DLL は、読み込むプロセスと同じ種類の CPU 向けのものしか読み込まれない。
  64 ビットの Windows では 32 ビットのアプリも動き、それには 32 ビットの
  DLL を 32 ビット用のレジストリに登録する必要がある。ARM64 の Windows では、
  ARM64 のアプリとエミュレーションで動く x64 のアプリが 64 ビット用の
  レジストリを共有し、一つの DLL しか登録できない。両方に読み込ませるには
  ARM64X 形式が要るが、Rust では作りにくい。
- 辞書サーバとの通信は文字列で行っており、CPU の種類に依らない。
- 言語モデル一式は Release から取得する (ADR-0036)。llama.cpp も公式の
  Release から取得している。

## 選択肢

### A. MSI がファイルを使う場所に直接置き、登録だけをカスタムアクションで行う

- 利点: MSI の定石どおり。修復で壊れたファイルが直る。
- 欠点: 使用中のファイルとぶつかる。更新のたびに再起動を求めるか、使用中の
  画面が出る。削除直後の入れ直しでも同じ。

### B. A を版ごとのディレクトリで行う

- 利点: 更新ではぶつからない。
- 欠点: 削除してから再起動しないまま同じ版を入れ直すと、ぶつかる。

### C. MSI は置き場に置くだけにし、使う場所への配置と登録は crystalskk-setup が行う

- 利点: MSI の置いたファイルは誰にも読み込まれないので、Windows Installer は
  使用中のファイルに一度も出会わない。使用中の扱いは、動いている改名の
  方式に任せられる。開発中の `install` と配布物の導入が同じコードを通る。
- 欠点: 使う場所のファイルは MSI の管理の外になる。修復と削除の片付けは
  カスタムアクションの責任になる。

## 決定

**C を採る。**

### 置くもの

MSI は `%ProgramFiles%\CrystalSKK\package\` に次を置く。ここから直接
読み込まれるものは無い。

- `crystalskk_tip.dll`
- `crystalskk-server.exe`
- `crystalskk-setup.exe`

言語モデルと llama.cpp は MSI に入れない。導入のときに取得する
(ADR-0031, ADR-0036)。MSI は小さく保たれ、置き場と使う場所に同じモデルが
二つ置かれることもない。

### カスタムアクション

操作を、誰として動くかで二つに分ける。

| 順 | 動く者 | すること |
|---|---|---|
| ファイルを置く前 | 導入する利用者 | 自分の辞書サーバに終わってもらう |
| ファイルを置いた後 (遅延) | LocalSystem | 置き場から使う場所 (`bin`) へ写す (使用中なら退ける)。COM と入力方式を登録する。言語モデルと llama.cpp を取得して置く |
| 終わった後 | 導入する利用者 | 設定ファイルを用意する。辞書サーバを起こす |

- **自動起動は辞書サーバが自分で登録する。** 起きたときに、自分の
  `HKEY_CURRENT_USER` の `Run` に自分を書く (すでにあれば何もしない)。
  CrystalSKK を使った利用者にだけ、次のログオンから効く。使わない利用者に、
  辞書と言語モデルを抱えたプロセスを常駐させない。
  `HKEY_LOCAL_MACHINE` の `Run` に書く案は、この理由で採らなかった。
- 他の利用者の辞書サーバは止められない。古い exe は退けられて動き続け、
  次のログオンで新しいものが立つ。残骸は次の導入で片付く。
- 他の利用者の設定ファイルは、TIP がフォーカスを得たときに足りない項目を
  尋ねる仕組みで用意される。
- 修復でも、遅延のアクションを同じように動かす。
- 削除では、ファイルを消す前に `crystalskk-setup uninstall` を動かし、
  登録を消して使う場所を片付ける。使用中で消せないものは、再起動したときに
  消える予約をする。他の利用者の `Run` に残った登録は消せないが、ログオンの
  ときに起動に失敗するだけで害はない。

このために `crystalskk-setup` に、昇格せずに機械全体の部分だけを行う入口と、
利用者の部分だけを行う入口を足す。元のファイルの場所は、`target/release` を
探すのではなく引数で渡す。

### CPU の種類

MSI は x64 向けと ARM64 向けの二つを作る。

| MSI | TIP の DLL | 辞書サーバ・llama.cpp |
|---|---|---|
| x64 | x64 (64 ビット用のレジストリ) と x86 (32 ビット用のレジストリ) | x64 |
| ARM64 | ARM64 (64 ビット用のレジストリ) と x86 (32 ビット用のレジストリ) | ARM64 |

- 辞書サーバは利用者ごとに一つで、どの種類の TIP とも話せる。
- ARM64 では ARM64 の DLL を登録する。Windows に付属するアプリや主要な
  ブラウザは ARM64 で動くので、入力する場面の多くに届く。エミュレーションで
  動く x64 のアプリでは使えない。
- ARM64 の MSI は、実機で確かめないまま出す。使った人の報告を待つ。

### 版と更新

- MSI の版は、ワークスペースの版 (`major.minor.patch`) にする。Windows
  Installer がアップグレードの判定に使うのは最初の三つだけである。
- `UpgradeCode` を固定し、メジャーアップグレードで入れ替える。
  ダウングレードは断る。
- 出した版の中身は替えない。直したいことがあれば版を上げる。

### 署名

当面は署名しない。SignPath の証明書が得られたら、MSI と中の exe・DLL に
署名する。

## 帰結

- 更新・入れ直し・削除直後の入れ直しのどれでも、再起動を求めずに済む。
  開いているアプリは古い DLL を使い続け、新しく開いたアプリから新しい版に
  なる。
- 使う場所のファイルが壊れても、MSI の修復は置き場しか見ない。修復で
  カスタムアクションが写し直すので、結果として直る。
- 導入に通信が要る。通信できなければ、並べ替えの効かないまま導入が終わる。
- `crystalskk-setup` の導入の手順が、開発とインストーラーで二通りの呼ばれ方を
  するようになる。どちらも同じ関数を通すこと。
- ARM64 では、エミュレーションで動く x64 のアプリで使えない。Rust で ARM64X
  を作れるようになったら見直す。
