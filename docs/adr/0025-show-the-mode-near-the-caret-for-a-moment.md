# ADR-0025: 入力モードは、切り替えたときにカーソルのそばへ短く出す

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0013, ADR-0015, ADR-0020, ADR-0024

## 背景

入力モードはトレイに出ている (ADR-0024) が、打っているときに目はカーソルに
ある。カーソルの近くで、いまのモードが分かるようにしたい。

## 選択肢

### A. キャレットの色を変える (SKKFEP)

アプリのキャレットを色付きの絵のキャレットに置き換える。

- 利点: 目を離さずに分かる。
- 欠点: Windows 標準のキャレットを使うアプリ (メモ帳、昔ながらの入力欄)
  にしか効かない。Chrome、Edge、Electron 系、Word、ストアアプリ、Windows
  Terminal はキャレットを自前で描く。他人のキャレットを奪うことにもなり、
  アプリが作り直すたびに打ち負ける。

### B. 切り替えたときに、カーソルのそばへ短く出す (CorvusSKK・MS-IME)

- 利点: どのアプリでも同じ形で出る (位置を教えてくれるアプリなら)。候補の
  窓の出し方をそのまま使える。
- 欠点: 位置を教えてくれないアプリでは出せない。

### C. 日本語モードのあいだ、カーソルのそばに印を置き続ける

CrystalSKK は入のとき英数が常態 (ADR-0013) なので、印があれば日本語になる。

- 利点: 見落としが無い。
- 欠点: カーソルを追いかける仕掛け (文書の変化とスクロールを聞く) が要り、
  印が文字にかぶる。

### D. 未確定文字の見た目でモードを表す

- 欠点: ひらがなの直接入力はすぐ確定するので、ほとんど目に入らない。

ほかに、Windows 11 の「テキストカーソルインジケーター」の色を切り替える案
(機械全体の設定を書き換えることになる) と、マウスポインタを変える案
(カーソルから遠く、ポインタはアプリの持ち物) も見送った。

## 決定

**B を採る。** 定型の部分 (位置の取り方、当てにならない位置の捨て方、画面の
端での逃がし方) は CorvusSKK の「入力モード表示」に倣う。

- **出すとき:** モードや入切を切り替えたとき。設定で、入力先 (文書) に焦点が
  入ったときにも出せる。打ちかけのあいだは出さない (未確定の文字列と候補の
  窓がそこにある)。
- **消すとき:** 決めた時間が経ったとき。打鍵が来たとき (打っている字に
  かぶる)。入力先が変わったとき。
- **絵:** トレイと同じ入力モードの絵 (ADR-0024)。大きさもトレイと同じ
  16 画素 (100% のとき。余白を入れて一辺 20 画素)。**打っている文字より
  目立っては困る。** 最初は 24 画素にして、大きすぎると言われた。
- **色:** アプリの明るさ (`AppsUseLightTheme`) に合わせる。窓が載るのは
  タスクバーではなくアプリの上なので、トレイとは見るものが違う。
  - 明るければシステムの色 (地は窓の色、縁は強調の色、絵は文字の色)。
  - 暗ければ黒い地 (`#2B2B2B`) に白い絵。**Win32 のシステムの色はダーク
    モードにしても白いまま**なので、こちらで決める。
  - ハイコントラストなら、明暗にかかわらずシステムの色。利用者の選んだ
    配色を上書きしない。
- **位置:** 選択範囲 (カーソル) の文字の位置 (`GetTextExt`) を、読むだけの
  編集セッションで尋ね、その真下に置く。作業領域 (タスクバーを除いた画面)
  の下に入らなければ上へ回す。CUAS 越しのアプリが返す「高さの無い、幅
  1 画素の矩形」は捨てる (CorvusSKK もそうしている)。
- **焦点を奪わず、クリックも下へ通す。** 一瞬出るだけの窓に、打鍵や
  クリックを取られてはならない。持ち主は入力先の窓にする (候補の窓で、
  持ち主の無い窓がアプリの描画面の下に潜ったことがある)。
- 入力先の焦点の変化は `ITfThreadMgrEventSink::OnSetFocus` で聞く。

### 設定

```toml
[mode_indicator]
on_switch = true      # モードや入切を切り替えたときに出す
on_focus = false      # 入力先に入ったときにも出す
duration_ms = 1000    # 出しておく時間
```

両方を `false` にすれば出ない。

## 帰結

- 位置を教えてくれないアプリでは出ない。候補の窓と同じ事情で、そういう
  アプリではそもそも候補の窓も出ない。
- C は、この窓を置き続ける形で後から足せる。そのときはカーソルを追いかける
  仕掛けが要る。
- 色の決め方 (`theme::Palette`) は、同じくダークモードで白いままの候補の
  窓にも使える。
- 見直す条件: 位置を教えてくれないアプリで困る場面が多いとき (Win32 の
  キャレットの位置 `GetGUIThreadInfo` を代わりに使う手がある)。
