# ADR-0009: 設定画面に出す絵は `.ico` ファイルとして置く

- ステータス: Accepted
- 日付: 2026-09-22
- 関連: PRD N-08 (C ツールチェインを要求しない)

## 背景

入力方式には絵が二つ要る。

- **入力方式そのものを示す絵** … 設定画面の一覧やトレイに出る。
  `ITfInputProcessorProfileMgr::RegisterProfile` に「絵のあるファイルと
  その中の番号」を渡して指す
- **入力モードを示す絵** … 言語バーの項目が `GetIcon` で返す `HICON`

前者を DLL 自身に向けていたが、その DLL に絵が無いため、設定画面には
絵の代わりに言語名 (「日本」) が出ていた。

絵を DLL に埋め込むには PE の資源が要り、資源を作るにはリソース
コンパイラ (`rc.exe` / `llvm-rc`) が要る。これは PRD N-08 の
「C ツールチェインを要求しない」と衝突する。

## 選択肢

### A. リソースコンパイラを使う

`.rc` を書き、ビルド時に資源を作って埋め込む。

- 利点: 一般的なやり方。ファイルが一つ減る。
- 欠点: 外部ツールチェーンが要る。`cargo build` だけで済まなくなる。

### B. `.res` を自前で組み立てる

資源ファイルの形式は単純なので、ビルドスクリプトで組み立てて
リンカへ渡すことはできる。

- 利点: 外部ツールチェーンは要らない。DLL に埋め込める。
- 欠点: 形式を自分で相手にすることになる。得るものは「ファイルが
  一つ減る」ことだけ。

### C. `.ico` ファイルを置いて、それを指す

**`RegisterProfile` が受け取るのはファイルであって、資源である必要は
ない。** `.ico` を指してよい。

- 利点: 外部ツールチェーンは要らない。絵の差し替えがファイルの
  差し替えで済み、DLL を作り直さなくてよい。
- 欠点: 置き場所にファイルが一つ増える。消されると絵が出なくなる。

## 決定

**C を採る。** 導入のときに `.ico` を書き出し、`RegisterProfile` には
そのファイルを指させる。

絵は GDI で描いて `.ico` の形に組み立てる。言語バーが返す `HICON` と
同じ描画を使うので、二つの絵が食い違わない。

B を採らないのは、得るものが「ファイルが一つ減る」ことしかないため。
A を採らないのは、周辺機能のために全体の性質を変えることになるため
(ADR-0004 と同じ理由)。

## 帰結

- 絵を差し替えるとき、DLL を作り直さなくてよい。`.ico` を置き換えて
  導入をやり直すだけで済む。
- 描いた絵と書き出した絵が同じ経路から出るので、ずれない。
- `.ico` が消えると設定画面の絵が言語名に戻る。入力そのものは動くので、
  書き出しに失敗しても導入は続ける。
- **「アイコンを入れる = リソースコンパイラが要る」は早合点である。**
  資源が本当に要るのは、ファイルではなくモジュールを指す仕組みだけ。
  ここではファイルを指せた。
