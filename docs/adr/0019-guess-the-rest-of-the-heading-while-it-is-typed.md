# ADR-0019: 打っている最中に見出し語の続きを当てる

- ステータス: Accepted
- 日付: 2026-09-23
- 関連: ADR-0001, ADR-0016, ADR-0017

## 背景

SKK の補完は Tab で明示的に呼ぶものだった。SKKFEP はそれとは別に、
**打っている最中に当て推量を出しておく**。二文字も打てば見出し語はだいたい
決まるので、残りを見せておいて、要るときだけ受け取る。

利用者からの要件は明確だった。**出る候補はひとつきり。だから戻るという
操作は存在しない。`.` 打鍵で補完し、変換して確定する、それだけ。**

## 決定

### 二つの操作を一つの仕組みに乗せる

`Completion { prefix, entries, chosen }` を `Composing` に持たせ、打鍵の
たびに引き直す。Tab は `entries` を順に巡り、`.` は出ている当て推量を
そのまま受け取る。**どちらも同じ操作で、押す前の状態が違うだけである。**

Tab の補完を土台に置いたのは、動的補完がその一部だからである。別々に
作れば、片方だけが壊れる。

### `.` は変換と確定まで進める

当て推量が出ている時点で、**その見出し語は辞書にあると分かっている**。
だから変換の結果を選ばせる手間は要らない。`.` 一打鍵で、受け取り・変換・
確定まで終わる。選び直したければ、受け取らずに space を打てばよい。

### 当て推量は「まだ打っていない残り」だけ

`ghost()` は `chosen` が無いあいだだけ、打った分を差し引いた残りを返す。
受け取れば `chosen` が埋まり、当て推量は消えて、ただの見出し語になる。
**ひとつきりしか出ないのだから、戻る先も無い。**

### 線を引かないことで区別する

当て推量には `TF_LS_NONE` を貼る (ADR-0017)。下線は打った文字のところで
終わり、その先に線が無ければ**まだ自分の文字ではない**と見て分かる。色で
薄く出す手もあるが、色は決めない方針である。

### 引くのは全ての辞書

ユーザー辞書だけでは、まだ一度も使っていない語が出ない。サーバが
**ユーザー辞書を使った順に、静的辞書を辞書順に**並べて返す (ADR-0016)。
前者が先なのは、直前に使った語のほうが要る見込みが高いからである。

### 出さない場面

- 見出し語が `COMPLETION_MIN` (2) 文字に満たないとき。一文字では当たらない。
- 送り仮名に入ったあと。見出し語はもう決まっている。
- abbrev (`/`) のとき。かなの見出しを当てても仕方がない。

## 結果

- `.` は当て推量が出ているときだけ奪う。出ていなければ普通に打てる。
  見出し語に句点を打つことはまず無い。
- Tab は当てるものが無ければアプリに渡す。**何も起きないキーを食べない。**
- 当てたばかりのものは引き直さない。巡っている最中に引き直すと、巡る先が
  そのつど変わってしまう。

### 窓は段階で姿を変える

当て推量が出ているあいだ、候補ウィンドウに `.: かんじ` の**一行**を出す。
押すキーがそのまま左に出るので、一覧の見せ方と揃う。一行なのは、出る候補が
一つきりで選ぶ操作が無いからである。

Tab で巡り始めたら**前後を並べる**。**次に何が来るかが見えないと、何度
押せばよいか分からない。** 区切り方は候補の一覧と同じにする (窓の高さが
打鍵のたびに変わると落ち着かない)。当てている行は**地と文字の色を入れ替えて
示す**。記号で示すより確かで、**フォントによって見た目が変わらない**。

### 窓に出すのは変換先

読みは見れば大抵分かる。窓に出して意味があるのは**変換した後の姿**の
ほうである。未確定の側には読みが出ているので、二つ合わせて読みと変換先の
両方が見えることになる。

そのために、出す分の変換先だけを引く。一度に全部引くと、打鍵のたびに辞書を
十何回も叩くことになる — 受け取る前は先頭の一つ、Tab で巡っていればその
ページ分だけでよい。

このとき `.` の案内は落とす。**同じキーが同じことをしないのに、出したまま
にはできない。**

これをシステムの候補一覧 (`ITfCandidateListUIElement`) には差し出さない。
補完は変換候補ではないので、混ぜるとアプリには「変換候補が出た」と見えて
しまう。

候補の一覧が出ているあいだは、そちらが手前である。もっとも補完は「まだ
変換していない」段階のものなので、二つが重なることはない。

## 見送ったもの

出すかどうかの設定。設定の仕組みがまだ無い。`COMPLETION_MIN` や、窓に
読みと変換先の両方を出す選択ともども、設定を入れるときに一緒に出す。
